# MentorSlicer Print Advisor MCP

The Print Advisor MCP sidecar exposes MCP tools over stdio and a small authenticated loopback API hosted by MentorSlicer. It reads context and can save changes to the tunable settings of the active filament/process profile as a **new user profile copy**, after explicit in-app approval. It never overwrites the source, silently changes the active profile, sends files, or starts a print. Printer controls (pause/resume/stop, fans, temperatures, speed, light, preheat, exhaust guard, slow cooldown) are sent only after a confirmation in MentorSlicer. Explicit exceptions: the exhaust guard and the slow cooldown send repeated commands after ONE confirmation, and a preheat switches the bed off by itself, without a dialog, when the printer stays idle (safety).

## Tools

- `get_print_context` — active printer/filament/process profiles and their parents, machine limits and capabilities, the current plate type with its bed temperature keys, the plate custom G-code, `edited_config` (a fixed subset of profile keys, without per-object overrides: use `analyze_model` for those) and `editable_profile_values` (the full source: every writable filament/process value of the selected profiles).
- `get_profile_values` — current values (with label, unit and limits) of any writable filament/process setting, filtered by keys or keyword.
- `get_parameter_schema` — schema metadata, filtered by profile class and keyword.
- `diagnose_defect` — targeted follow-up questions and low-risk checks.
- `recommend_parameter_changes` — cautious, context-aware trial suggestions. The suggestions are not applied.
- `preview_profile_changes` — validates a patch and returns the exact diff; the proposal remains in memory and expires after 10 minutes (or when the app closes).
- `apply_profile_changes` — asks MentorSlicer to show the diff and obtain explicit approval, then saves a separate copy without selecting it. The copy inherits from the same parent as a manual "Save as": the system profile when the source is one, otherwise the source's own parent, so untouched values keep following it.
- `get_slice_result` / `slice_and_measure` — read, or produce by slicing the current plate (always the plate shown in MentorSlicer; it never switches plate), the estimated time, layers, filament used (mm, g), time per feature, slicer warnings and toolpath-outside flag, to compare before and after a change.
- `configure_heat_soak` — prepares a filament profile change (`heat_soak_time`, `heat_soak_bed_temp`, optionally `during_print_exhaust_fan_speed`) that, before the printer start G-code, holds the bed at temperature with the nozzle cold and the exhaust fan off (`M190`, `G4`), to warm the chamber of an enclosed printer without chamber heater. The two `heat_soak_*` filament options are added to the slicer core by this fork; the change is saved through `apply_profile_changes` like any other.
- `set_layer_schedule` — programs bed, nozzle and chamber temperatures and the case/chamber fan (`M140`, `M104`, `M141`, `M106 P3`, or `P1` on CX printers) from given layers onward, as plate custom G-code (the same data as "Add custom G-code" on the preview layer slider). It shows the schedule in MentorSlicer and needs confirmation; each call replaces the previous Print Advisor schedule and an empty list removes it. Custom G-code added by the user is never touched, and a layer that already has one is refused. Part and auxiliary fans are recomputed by the cooling logic every layer, so they are set through the filament profile. Not available when printing object by object. `chamber_temp` is refused when the printer has no chamber temperature control (`support_chamber_temp_control`).
- `get_printer_status` — live LAN printer state from the device manager connection (state, progress, layers, times, nozzle/bed/chamber temperatures and maximums, fans, errors, filament sensor `materialDetect`/`materialStatus`, `ai*` detections, `speedMode`, `sleepMode`, `printStartTime`, `printFileName`) and recent finish/error events; a device with an active error gets `error_explained`. Windows notifications on finish/failure/abort/error while Print Advisor is enabled.
- `explain_printer_error` — explains a printer error code (numeric key such as `2565` or display code such as `CB2565`/`AC0117`) with the table of the device page (`src/errorCodeTable.ts`, 286 entries, taken from Creality's compiled bundle) and an Italian text for K1-series codes (`src/errorCodes.ts`). After the device page bundle is updated from upstream Creality Print, regenerate the table with `node scripts/extract-error-codes.mjs <deviceMgr bundle defining errorJson> src/errorCodeTable.ts`.
- `control_print` — pause, resume or stop the selected printer after in-app confirmation (never starts a print). The command goes to the Device page asynchronously: the tool returns a `request_id`, and `get_printer_status` reports the page's answer per action in `print_control_results` (with that `request_id`; also for the bed command of `preheat_chamber`) and the newest one in `last_print_control_result`; a failure is logged, written to the change history and notified. A failed bed switch-off is sent again directly to the printer; a failed preheat start is no longer followed.
- `set_fan`, `adjust_print_temp`, `set_print_speed`, `set_light` — live printer controls through `/v1/device_control`, each after in-app confirmation: one fan (`part` = nozzle fan P0, `side` = big side fan P2, `exhaust` = rear exhaust P1 on the K1C) to 0-100%, nozzle/bed target during a print (profiles unchanged), speed mode 25/50/100/125, chamber light. MentorSlicer writes the command to the printer WebSocket (`WebSocketProxy::SendToDevice`, the LAN connection of the Device tab, which must be open); verify with `get_printer_status`.
- `camera_snapshot` — one frame from the printer camera, returned as MCP image content. The device page takes the first visible, playing WebRTC `<video>` (open the detail view of the right printer when there are several); an MJPEG-only stream cannot be captured. MentorSlicer reports the printer `address` shown by the page and `address_matched`; the sidecar says "dalla stampante selezionata" only when `address_matched` is true and otherwise warns that the frame may come from another printer. Read-only.
- `preheat_chamber` / `get_preheat_status` — heats the bed of an idle printer (confirmation) with an optional chamber target and `max_minutes` (5-120, default 60) and returns immediately. If the printer is still idle, MentorSlicer switches the bed off by itself after `max_minutes` (`timeout`), 20 minutes after the target or a plateau (`idle_after_target`, `idle_after_plateau`) and when the server stops. A print start ends the monitor and leaves the bed to the print (`print_started`). On telemetry loss the outcome is `telemetry_lost` and the bed may still be hot: the switch-off is sent when the telemetry returns. Only one preheat is followed at a time: a preheat on another printer is refused while the first is still running or waiting for its switch-off. `bed_temp` 0 ends it and switches the bed off.
- `get_monitor_status`, `set_exhaust_guard`, `slow_cooldown` — background monitor state; exhaust guard that re-sends exhaust off whenever the firmware switches the rear exhaust on during an ASA/ABS print. On the K1C this does not work: above about 35-37 °C chamber the firmware ignores `fanCase:0` and `M106 P1 S0`, so the guard keeps sending an ignored `fanCase 0` and logs the re-enables (after 6 ignored sends it slows to one every 2 minutes: `ignored_sends`, `slowed_down`); the real remedies are aluminium tape on the rear grille (remove it for PLA) or the firmware threshold (root access). The guard needs `activate_air_filtration=1` and `during_print_exhaust_fan_speed=0` and a known print identity, `printStartTime` + file; one confirmation per print; disarms at print end, on a new print or after a telemetry gap over 2 minutes; pauses at the chamber ceiling (`maxBoxTemp - 5`, 55 °C on the K1C); stepped bed cooldown after a print, checked again after the confirmation so it never heats the bed, ending at `to` (`to=0` switches the bed off; `{cancel:true}` stops it).
- `list_print_logs`, `get_print_log`, `record_print_verdict`, `suggest_recipe` — per-print logs (temperatures, fan events, summary), the user's verdict (ok/warp/detach/stringing/under_extrusion/other), and a heuristic digest of past prints of a material. `get_print_log` returns at most 500 points and the newest 200 events and 200 verdicts (`events_truncated`/`verdicts_truncated` give the totals). `record_print_verdict` is a change: one verdict per print log (a second one gets HTTP 400), refused with HTTP 409 while a dialog is open in MentorSlicer, and not retried after a timeout. `suggest_recipe` runs in the sidecar and never changes anything: 5 s per call, 30 s overall (`partial=true` when cut short), completed prints without a verdict count as unknown, and the built-in K1C ASA examples are returned only when the printer is a K1C.
- `list_archived_prints`, `reopen_archived_project` — archive of successful prints (the list returns only the essential `metadata.json` fields, with long texts shortened). After a completed print, once the bed is below 40 °C, MentorSlicer asks the user how it turned out (dialog plus notification): "Good, archive" records the verdict `ok` and copies the open project (3MF), the G-code of the current plate, the print log and a camera photo (if the Device tab is open) into `data_dir/print-advisor/archive/<date>_<name>/` with a `metadata.json` that says what was skipped and why; "Defects or failed" asks a reason (detached, warping, stringing, under-extrusion, other + note) and records it as `detach`/`warp`/`stringing`/`under_extrusion`/`other` in the print log, same format as `record_print_verdict`; "Later" keeps the question pending (`pending_verdict.json`) until the next start of the Print Advisor server. While the verdict dialog is open, MentorSlicer answers HTTP 409 to every change until the user answers it. `reopen_archived_project` opens a temporary copy of the archived 3MF as an untitled project after in-app confirmation (the archive is never overwritten; "Save" asks for a name) and never starts a print; the printer, filament and process profiles embedded in the project become the active selection, and the result reports `presets_before`/`presets_after`.
- `get_overhang_regions`, `list_support_volumes`, `add_support_volume`, `remove_support_volume` — overhang clusters of one object with the expert support workflow, and support enforcer/blocker volumes (box or cylinder) added after confirmation; only `Advisor enforcer…`/`Advisor blocker…` volumes can be removed.
- `start_calibration` / `compute_calibration_result` — generates the built-in temperature, flow, pressure advance, retraction or max volumetric speed test on a new project (confirmation) and converts the user's reading into the profile value. MentorSlicer refuses out-of-range tests: temperature tower in multiples of 5 with end at most start - 5, inside the filament range and the printer maximum, pressure advance up to 2, retraction up to 10 mm, volumetric speed up to 60 mm³/s. Pressure advance is read as `start + step * floor(height_mm)`, because the tower G-code changes value once per whole millimetre (`GCode.cpp`, `int(print_z)`). The tower must fit the printer's `printable_height` and the steps are bounded (pressure advance 0.001-0.5, retraction 0.01-2 mm, volumetric speed 0.1-10 from at least 0.5). The generators replace the open project (MentorSlicer asks to save it) and leave the edited profiles with unsaved changes, some beyond the Print Advisor limits (the max volumetric speed test raises `filament_max_volumetric_speed`), so profile changes are refused until the user reselects the profiles discarding them; the max volumetric speed test also switches the selected filament to the preset of extruder 1.
- `preflight_check` — printer limits, material/plate/nozzle compatibility, speeds and the G-code of the current slice. For ASA/ABS it adds advisory findings (never blocking, each with a `data` object; only some carry a `data.advice` keyword): `glue_on_smooth_pei_large_part` (smooth PEI plate and a part over 80 mm on the XY side: glue stick), `chamber_cold_preheat` (live chamber reading under 30 °C on an idle printer: `preheat_chamber` before sending and a heat soak of at least 30 min below 20 °C or 15 min at 20-30 °C, the same figures as the `cold_room`/`cool_room` findings) and `chamber_unknown` (no recent telemetry, not repeated when `printer_data_stale` was already reported: open the Device tab instead of guessing). The sidecar adds a top-level `advice` map (code → text) to the result for the advisory codes it knows.
- `get_bed_type` / `set_bed_type` — the plate type (`curr_bed_type`, a project setting, not a profile): the project default of the sidebar, the override of each plate, the types the printer offers and the bed temperatures of the active filament for each (`*_plate_temp`, `*_plate_temp_initial_layer`). `set_bed_type` changes the project default (scope `project`) or one plate's override (scope `plate`, `plate_number`, `default` removes it) after a confirmation that shows before/after and the resulting bed temperatures; it uses the same Plater entry points as the sidebar combo box and the Plate Settings dialog, is refused while slicing or exporting, and the plate must be sliced again.
- `analyze_model`, `arrange_plate`, `set_object_settings` — object analysis (size, mesh, overhang estimate, support hints), auto orient/arrange and per-object overrides, with confirmation.
- `list_profiles`, `compare_profiles`, `delete_profile_copy`, `export_profile`, `get_change_history` — profile library and the persistent change log (`data_dir/print-advisor/history.jsonl`).
- `get_material_guide` — typical values and pitfalls per material.
- `rollback_profile_update` — asks for confirmation before deleting an unchanged, inactive copy created in this session; it refuses if the copy is active, modified, protected, or used as a parent.

Writable settings are decided by MentorSlicer (`advisor_key_writable` in `PrintAdvisorServer.cpp`): every numeric, percent, boolean or enum setting owned only by the filament or only by the process profile, including bed temperatures per plate type (`cool_plate_temp`, `eng_plate_temp`, `hot_plate_temp`, `textured_plate_temp` and their `_initial_layer` variants), chamber temperature, cooling, retraction overrides, speeds, walls, infill, support and brim. Free text (G-code, names, notes, compatibility conditions, `inherits`), points, material identity keys (diameter, support/soluble flags, temperature range) and extruder assignments are read-only. A proposal holds up to 40 changes. Scalar settings take one value. Vector settings require the complete array with the same component count as the source profile; null slots must remain null, so the extruder count cannot change. Printer profiles are not writable through proposals, and object overrides and project settings are not part of a proposal: they have their own tools with their own confirmation (`set_object_settings` for per-object overrides, `set_bed_type` for the plate type). Besides the schema limits, absolute values must stay within safety bounds (`check_advisor_safety`): nozzle temperatures 150-350 °C and inside the filament's own `nozzle_temperature_range_low/high`, plate temperatures 0-120 °C, chamber 0-80 °C, flow ratio 0.5-1.5, speeds 0-1000 mm/s, accelerations 0-50000 mm/s², layer height 0.04-0.6 mm. Profiles loaded from a file (external) cannot be used as source; save them as user profiles first.

## Prerequisites

- A MentorSlicer build (the Print Advisor is always compiled in). The build puts `mentorslicer-mcp.exe` next to `MentorSlicer.exe`: the sidecar packaged with its own Node.js runtime, so users need neither Node.js nor npm.
- Start MentorSlicer, open **AI Integration → Print Advisor MCP…** and press **Enable**. The endpoint stays disabled by default. The same dialog explains what the integration allows, shows its state and the descriptor path, and gives the `claude mcp add` command below already filled in with the path of the `mentorslicer-mcp.exe` next to the running MentorSlicer, with a copy button.
- While enabled, the app creates `cache/print-advisor/endpoint.json` in its data directory (`%APPDATA%\MentorSlicer` on Windows). The sidecar reads it from there by itself; `MENTORSLICER_ADVISOR_DESCRIPTOR` overrides the path, which is needed only for a copy started with `--datadir` (the dialog then adds it to the command). The descriptor contains a session token and is removed when the app shuts down or the integration is disabled; do not copy it into prompts or source control.

## Build the executable

`mentorslicer-mcp.exe` is a Node.js single executable application: `scripts/build-exe.mjs` bundles `src/index.ts` with esbuild into `dist/mentorslicer-mcp.cjs` and injects it into a copy of the `node.exe` that runs the script (postject). `build_exe_only.bat` and `build_release_vs2022.bat` call it through `tools\build-mcp-exe.bat`, which runs `npm ci` the first time and copies the result into `build\src\Release`; the install target and `tools\publish-stable.ps1` take it from there. Node.js 20 or later is therefore needed **only on the build machine**; without it the build goes on with a warning, and the dialog falls back to the Node.js setup below. The executable is rebuilt only when `src/`, `package-lock.json` or the script change (`--force` rebuilds anyway). By hand, from this directory:

```powershell
npm install
node scripts/build-exe.mjs --copy-to ..\..\build\src\Release
```

The result is about 90 MB (the Node.js runtime of the build machine) and unsigned: the injection invalidates the signature of `node.exe`, and postject warns about it. A running copy (an MCP client keeps it open) cannot be overwritten on Windows: the build script and `publish-stable.ps1` rename it to `mentorslicer-mcp.exe.old-<time>` and delete it on a later run; the client uses the new file at its next start.

The MCP transport uses the official TypeScript MCP server SDK and stdio. Keep stdout reserved for MCP; diagnostics are emitted by the SDK/runtime, not with `console.log`.

Type check with `npm run typecheck`. Smoke test with `npm run smoke` (sources through tsx) or `node scripts/smoke.mjs --exe dist/mentorslicer-mcp.exe` (the packaged executable). Source layout: `src/index.ts` (server, profile and slicing tools), `src/appClient.ts` (descriptor and authenticated loopback client), `src/tools/device.ts`, `src/tools/monitor.ts`, `src/tools/supports.ts`, `src/tools/plate.ts` (plate type), `src/tools/archive.ts` (print archive), `src/errorCodes.ts` with the generated `src/errorCodeTable.ts`.

## Claude Code

Register the server once, for every folder (`--scope user`), with the path of the executable next to MentorSlicer (copy the command from the dialog, or replace the path):

```powershell
claude mcp add mentorslicer-advisor --scope user --transport stdio -- "C:\MentorSlicer\mentorslicer-mcp.exe"
```

The path above is the stable copy made by `tools\publish-stable.ps1`; for the release zip it is `<folder>\MentorSlicer-<version>-win64\mentorslicer-mcp.exe`. `claude mcp add` refuses a name that is already registered: remove the old entry first with `claude mcp remove mentorslicer-advisor -s user`.

For a copy started with `--datadir`, add the descriptor before `--` (the dialog does it): `-e "MENTORSLICER_ADVISOR_DESCRIPTOR=<data folder>\cache\print-advisor\endpoint.json"`. Put the server name before `-e`/`--env`: the option is variadic, so a name placed after it is parsed as another environment variable and the command fails with "Invalid environment variable format".

The MentorSlicer data directory is `%APPDATA%\MentorSlicer` (there is no version subfolder; only an explicit `--datadir` adds `MentorSlicer\7.3 Alpha`). The descriptor path is stable across app restarts even though the token changes, so the registration does not need updating. An older registration (the `node … tsx … src/index.ts` command, or `creality-print-advisor` with the old variable), possibly in the `local` scope of a project folder, must be removed first: `claude mcp remove mentorslicer-advisor -s local` (and `claude mcp remove creality-print-advisor -s local` for the old name) from that folder, under every spelling Claude Code knows (for example `C:\…` and `c:\…`). Otherwise the project registration hides the user one.

Verify with `claude mcp get mentorslicer-advisor` (expects `Connected` while MentorSlicer is running with the integration enabled), then start a new Claude Code session or use `/mcp` so the tools are loaded. The tools are then named `mcp__mentorslicer-advisor__*`.

### Without the executable (development)

A build made without Node.js has no `mentorslicer-mcp.exe`. The sidecar can then run from its sources: install Node.js 20 or later, run `npm install` in this directory and register `node "<repo>\tools\print-advisor-mcp\node_modules\tsx\dist\cli.mjs" "<repo>\tools\print-advisor-mcp\src\index.ts"` as the command (the dialog shows it filled in when MentorSlicer runs from the source tree).

## Codex

Add a local stdio MCP server in the Codex configuration (replace the path with the one next to MentorSlicer, as for Claude Code):

```toml
[mcp_servers.mentorslicer_advisor]
command = 'C:\MentorSlicer\mentorslicer-mcp.exe'
```

For a copy started with `--datadir`, add `[mcp_servers.mentorslicer_advisor.env]` with `MENTORSLICER_ADVISOR_DESCRIPTOR = '<data folder>\cache\print-advisor\endpoint.json'`. The Codex CLI also supports `codex mcp add mentorslicer_advisor -- <path of mentorslicer-mcp.exe>`; `codex mcp list` shows configured servers. The config location is `~/.codex/config.toml` by default; a project-scoped `.codex/config.toml` is also supported by Codex for trusted projects.

## Trust and security

- **What the executable is**: the sidecar sources bundled into a copy of the `node.exe` of the build machine (Node.js single executable application). It contains the Node.js runtime of that machine (`process.versions.node`, 24.13.1 for the build of 2026-10-25) and the npm packages locked in `package-lock.json`. It is built locally from this repository; no binary is downloaded at build time besides the npm packages.
- **Not signed**: injecting the sidecar invalidates the OpenJS signature of `node.exe`, so the build removes it first with `signtool remove /s` when the Windows SDK is installed. Windows runs the unsigned file when an MCP client starts it, but antivirus or SmartScreen policies that require signed executables may block it; in that case use the Node.js setup ("Without the executable") or sign the file with your own certificate.
- **Updates**: the embedded Node.js does not update itself. The build rebuilds the executable when the Node.js version of the build machine changes (and `node scripts/build-exe.mjs --force` rebuilds it anyway); then run the normal build and `tools\publish-stable.ps1` or `tools\make-release.ps1`. Do it after a Node.js security release or an update of the MCP SDK.
- **What it can reach**: it talks only to MentorSlicer on `127.0.0.1`, with the session token read from `endpoint.json`; the token is never returned to the client or logged. It opens no port of its own and runs only while the MCP client keeps it open. It accepts no file paths or shell commands from the client: exports go through MentorSlicer's own save dialog, and archived prints are addressed by archive name.
- **Approval**: a confirmation in the MCP client is not an approval in MentorSlicer. Every change still asks for confirmation in MentorSlicer's own dialog (`AdvisorConfirmDialog`), and the Print Advisor never starts a print.
- **Registration**: `--scope user` makes the tools available in every Claude Code project of this Windows user. Use the default `local` scope instead if only one folder should see them.

## Troubleshooting

- If the sidecar reports that MentorSlicer is not open, enable Print Advisor in MentorSlicer (**AI Integration → Print Advisor MCP…**). For a copy started with `--datadir`, set `MENTORSLICER_ADVISOR_DESCRIPTOR` to its descriptor file.
- If the app is closed or the descriptor is stale, restart MentorSlicer and reconnect the MCP server.
- If no options are returned, confirm that the MentorSlicer GUI has finished initializing.
- Every change opens a confirmation (`AdvisorConfirmDialog`) inside MentorSlicer. Keep the app open while confirming; the MCP call waits up to 610 s (the app keeps the dialog up to 600 s). Timeouts of the sidecar (`src/appClient.ts`): 610 s for every change (including `record_print_verdict`, `set_bed_type`, `reopen_archived_project`) and for the reads that run on the MentorSlicer GUI thread and can wait behind a long task (`preflight_check`, `analyze_model`, `compare_profiles`, `get_overhang_regions`, `get_bed_type`); 15 s for `camera_snapshot`, `get_print_log`, `list_support_volumes`, `list_archived_prints` and the start of `slice_and_measure`; 5 s for the other reads; `suggest_recipe` 5 s per call and 30 s overall. A timed-out change is reported with "Non ripetere la richiesta in automatico": check first whether it was applied. The sidecar never follows HTTP redirects, and a malformed `endpoint.json` is reported as "Descrittore endpoint.json non valido".
- HTTP 409 means another request or a dialog is already open in MentorSlicer ("Un'altra richiesta è in corso…", "Chiudi le finestre aperte…"). Nothing was done. The assistant must not retry on its own: the user closes the open window and asks again if they want to; the sidecar never retries a change on its own. Read-only tools, preview_profile_changes included, keep working while a confirmation dialog is open; while a change is being applied outside its dialog (e.g. a project loading) they wait and may hit their timeout. HTTP 503 means MentorSlicer is serving its maximum number of connections and refused the request before reading it: nothing was done, and the sidecar retries it automatically (after 300, 800 and 1500 ms); 409 is never retried. The end-of-print verdict dialog counts as an open window: until the user answers it, every change gets 409.
- Results are compact JSON (no indentation) to keep large answers small.
- The source, printer, and other active profile snapshots must remain unchanged between proposal and approval. If they change, request a fresh preview.
