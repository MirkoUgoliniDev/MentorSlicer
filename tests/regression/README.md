# Regressione G-code del ramo `lean`

Confronta il G-code prodotto dalla build in prova con la baseline `F0` (build pre-lean) sugli stessi
progetti `fixtures/*.3mf`. Specifica completa: `doc/specs/F0-baseline-verifica-spec.md`.
Node 20+, nessuna dipendenza. Niente di tutto questo compila o avvia la GUI.

## Eseguire

```
node tests/regression/slice-fixtures.mjs --out tests/regression/out/F3 [--exe <MentorSlicer.exe>] [--only a,b] [--runs 2]
node tests/regression/compare-gcode.mjs --baseline-dir tests/regression/baseline/F0 --candidate-dir tests/regression/out/F3 --phase F3
node tools/verify-phase.mjs --phase F3 --slice        # tutto in un colpo (build, nomi rimossi, G-code, patch web, sidecar)
```

- `slice-fixtures.mjs` usa la CLI (`MentorSlicer.exe --cli --slice 0 ...`; la DLL si chiama `<nome exe>_Slicer.dll`, quindi funziona anche con il vecchio `CrealityPrint.exe` della baseline) con un `--datadir` vuoto e
  `TEMP`/`TMP` propri sotto `<out>\_work`: non tocca `%APPDATA%` e non serve la GUI. Non avviare una
  build mentre gira: il task di build chiude ogni `MentorSlicer.exe` (e il vecchio `CrealityPrint.exe`) sotto `build*`, CLI compresa.
  Percorsi senza spazi. Con `--runs 2` affetta due volte e segnala come FAIL ogni differenza.
- `compare-gcode.mjs` normalizza prima di confrontare (vedi sotto), poi: `IDENTICAL`, `DIFFERENT`
  (prime righe diverse con sezione, layer, z, `TYPE`, oggetto, e differenze di chiavi nel blocco
  `CONFIG`), `MISSING`, `EXTRA`. Uscita 0 identico, 1 differente, 2 uso, 3 file mancante/illeggibile.
  Legge anche `.gcode.gz`. `--hash` stampa solo lo sha256 normalizzato.
- `out/` è generata e ignorata da git.

## Rigenerare la baseline

Solo con la build del tag `pre-lean` (oppure la copia congelata `C:\CrealityPrint-prelean`,
`tools\publish-stable.ps1 -Dest C:\CrealityPrint-prelean -NoShortcut`), mai con la build candidata:

```
node tests/regression/slice-fixtures.mjs --out tests/regression/out/F0 --runs 2 [--exe C:\CrealityPrint-prelean\CrealityPrint.exe]
```

poi comprimere i `.gcode` in `baseline/F0/*.gcode.gz` (`node:zlib`) e aggiornare `baseline/F0/manifest.json`
(`fixture_sha256`, `sha256_normalized`, `check_ok`). `verify-phase.mjs` rifiuta il confronto se lo
sha256 di una fixture non coincide con il manifest.

## Cosa viene mascherato (`masks.json`)

Righe che cambiano a ogni esecuzione o per scelta della fase, non per il percorso di stampa:

| regola | riga | azione |
|---|---|---|
| `generated_by` | `; generated by Creality_Print V... on <data> at <ora>` | sostituita (timestamp; nome e versione cambiano in F8) |
| `creality_uuid` | `; creality_uuid: ...` | sostituita (UUID casuale) |
| `task_id_pending`, `task_id` | `; creality_task_id[_pending]: ...` | tolte (solo GUI, rimosse in F1) |
| `profile_version` | `; profile_version: ...` | tolta (solo GUI; regola "soft", resta con `--strict`) |
| blocchi thumbnail | `; THUMBNAIL_BLOCK_START..END`, `;gimage:`/`;simage:`, bigtree | tolti (solo GUI, dipendono dalla GPU) |
| `fixture_marker` | `; PRINT_ADVISOR_FIXTURE: ...` | tolta (solo fixture ritagliate) |

Non vengono mascherati, perché deterministici e proprio ciò che si vuole controllare: tempi stimati,
`M73`, numero layer, filamento usato, `EXCLUDE_OBJECT_DEFINE` e tutto il blocco `CONFIG`.
Una differenza giustificata da una fase va in `phase_rules` di `masks.json` con un campo `why`.
